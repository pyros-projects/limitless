# Assessment Contract

## Formative lesson assessments (non-failable)

Purpose: reveal capability, not gate progress.

Rules:
- Every fully written lesson gets one formative check.
- Record outcome as notes on strengths/gaps (`passed: n/a-formative` or equivalent).
- Never tell the learner they "failed the lesson" or block the next lesson on formative score.
- Weak results → targeted drills / remediation suggestions, then continue.
- Update `learner.md` capability fields after each formative.

Good formatives match the domain:
- Academic: short proof/problem check + misconception probe
- Physical: filmed checklist / RPE honesty / setup standards (diagnostic)
- Creative: constrained performance take + reflection rubric
- Language: can-do prompt with observed breakdown notes

## Capstone (failable)

Purpose: gate the next tier.

Rules:
- Exactly one capstone per emitted tier.
- Publish **explicit pass criteria** before the attempt (measurable / observable).
- Fail → remediation path + re-attempt with fresh instances (new problems, new loads, new charts) — do not recycle the identical item.
- Pass → record `capstone_result: pass` with dated notes; only then is Continue mode allowed to author the next tier.
- Capstone must test the tier's actual competence signal (not trivia about the syllabus).

## Anti-patterns

- Using lesson quizzes as pass/fail gates
- Capstones that are generic "quiz yourself" with no domain performance
- Writing five phase projects that each feel like soft gates without one clear failable tier capstone
- Skipping formatives because "the capstone will catch it"
