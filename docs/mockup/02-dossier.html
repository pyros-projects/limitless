Retrieval, packaged.

Mneme does not ask you to install a retrieval service. It ships one — managed, sidecar, and deliberately subordinate to Mneme's own ranking.

current-best understanding · grounded in 4 sources · 1 open contradiction · vintage stated, not hidden

premise gate

This compile assumes the question is "how does Mneme package retrieval as part of the product," not "which embedding model is best." If you're asking the latter, that's a different dossier.

01The answer

Mneme ships QMD as a managed sidecar, not as a user-installed dependency. mneme init installs ~/.mneme/bin/qmd and the configured retrieval models; mneme bind <host> writes the host's MCP entry to launch the same managed qmd mcp over stdio — the proven transport.1,2

The critical invariant: QMD provides candidate retrieval; Mneme owns product-ranking semantics. Collection filters are not layer priority. mneme ask merges and ranks results with explicit layer weights so compiled/ can outrank insights/, insights outrank memory/, and captures/ stays a deeper-excavation path.3 This prevents "QMD decided what matters" from becoming invisible product logic.

02Support

  • ADR-001 records the managed-sidecar decision over three rejected alternatives (in-process, optional install, hosted).1
  • The reference integration — claude-knowledge ↔ QMD — already proves the stdio MCP + multi-collection shape Mneme adopts.
  • KG evidence: hybrid lex+vec+hyde search with RRF outperforms pure keyword or pure semantic for agent memory.4

03Complications

mneme doctor must treat retrieval as a product subsystem, not a troubleshooting appendix: model availability, index freshness, transport health, host-MCP binding health, fallback when vector search is unavailable, and whether layer-priority ranking is being applied.

Index freshness is load-bearing for trust. A QMD miss must not read as "the memory doesn't exist" when the index is stale relative to the newest vault file — surface staleness, never silently serve it.
