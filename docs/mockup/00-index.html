What could Mneme look like?

Three paradigms for the same product — one local-first memory and knowledge substrate for AI agents. Same vault data, three completely different positions on a single line in the spec.

▸ the line these mockups exist to test
"MVP Non-Goals: no custom UI … Obsidian can be the human viewer. Mneme is the agent-operated substrate and CLI/MCP surface."

That's a strong, deliberate stance — and the right default for v0.1. But "no UI" deserves to be pressure-tested, not assumed. Each paradigm below argues one position on that line: agree, find-the-surface-anyway, or disagree on purpose. Walk all three and decide where the line actually sits.

How to read these

  1. Don't evaluate implementation. These are self-contained HTML clickdummies with mock data — no backend, no live vault. Judge the position and the information architecture, not the stack.
  2. Compare the same moment across all three. Every paradigm renders mneme status, the dossier on retrieval-packaging, a mneme ask result, and the boot budget. The differences are the point.
  3. Notice what each one refuses. Console refuses chrome. Dossier refuses interactivity. Atlas refuses the spec's "no viewer" call. Restraint is a feature here.
  4. Then pick the line. The real question isn't "which is prettiest" — it's: does Mneme stay CLI-only (Console), design only the dossier (Dossier), or build a viewer (Atlas)?
